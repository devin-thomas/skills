# Implementation contract

Use this reference when building or auditing a website agent handoff based on [Agent Prompts](https://agent-prompts.vercel.app/) ([`devin-thomas/agent-prompts`](https://github.com/devin-thomas/agent-prompts)). These are design and verification rules, informed by the field study and the reference implementation.

## Inputs and sources of truth

Keep one canonical task definition per handoff containing the task ID, display name, guide slug or URL, specific outcome, and default or selectable agent IDs. In `agent-prompts`, tasks resolve through a single helper:

`Read ${location.origin}/guides/${task.guide}.md and ${task.outcome}, following its scope and verification steps.`

Generate the inspection dialog (`#prompt-dialog`), character and word counts (`${[...text].length} characters · ${text.trim().split(/\s+/).length} words`), clipboard string, and any supported launch URL (`https://cursor.com/link/prompt?text=${encodeURIComponent(text)}`) from that same resolved string. UI chrome, filter state, logo treatment previews, and analytics events are never part of the payload.

Keep an explicit agent registry mapping product IDs (`chatgpt`, `claude`, `gemini`, `claude-code`, `codex`, `cursor`, `antigravity`, `grok-bot`, `grok`) to accurate display names (`ChatGPT`, `Claude`, `Gemini`, `Claude Code`, `Codex`, `Cursor`, `Antigravity`, `Grok Bot`, `Grok`), permitted SVG assets (`-original.svg`, `-black.svg`, `-white.svg`), whether the original mark is monochrome (`chatgpt`, `cursor`, `grok-bot`, `grok`), and verified launch capabilities. Record the source and check date for any client deep link. A product logo identifies the tool; it is not evidence that deep links, MCP connections, or repository permissions are configured.

## Public guides and project continuation

Use deterministic URLs for instruction resources (`/guides/branded-handoff.md`, `/guides/continue-project.md`, `/guides/contact-form.md`, `/guides/theme-switcher.md`, `/guides/newsletter-form.md`, and `/llms.txt`). Each guide must return readable plain Markdown rather than an SPA shell, login page, challenge, or missing-file fallback. Relative links inside a guide (such as `../examples/project-handoff.md`) must resolve in the transport the agent uses.

- **Feature and setup guides:** State the target scope, reuse the destination project's existing components, styles, and backend/secret conventions, specify required states (idle, submitting, success, recoverable error) and keyboard/mobile checks, and build a clearly labeled local demo that does not transmit or store personal data when no backend is configured.
- **Project continuation handoffs (`/guides/continue-project.md` and `/examples/project-handoff.md`):** Keep the continuation pattern agent-independent and grounded in records already inside the visitor's repository (`PROJECT.md`, roadmap, or handoff docs). Instruct the agent to treat an existing handoff as a starting point to verify against the working tree, never assuming an interrupted step succeeded or an earlier check still passes. After completing the next unfinished step and running relevant checks, the agent updates the same record (or creates a concise `PROJECT.md` covering goal, current state, next task, relevant files, and verification to perform) using repo-relative links and excluding credentials, personal filesystem paths, machine details, and raw session logs.
- **Authorization boundary:** A copied prompt or linked public guide operates strictly within the visitor's existing instructions and permissions. Never treat an example guide or handoff record as authorization to deploy, send real emails, subscribe real addresses, add paid services, or modify external accounts.

## Inputs → states → outputs

| Input / event | State and visible output | Payload / effect |
| --- | --- | --- |
| Task and required inputs available | Compact copy control; named agent or logo cluster visible in opening phone screen | One complete resolved bootstrap |
| Required input missing | Short request for that input; copy unavailable | No unresolved template or placeholder copied |
| Shared agent-independent task (`#format-01`, hero, `#format-07`) | Shared copy button with logo cluster and adjacent or accessible supported-agent names | Same resolved payload across supported agents |
| Agent picker selection (`#format-02`) | Named option buttons with authentic marks and `aria-pressed="true"` on the active choice; button label updates (`Copy for ${selectedAgent}`) | Resets prior copy feedback on the picker button; copies task payload for selected agent |
| Contextual prompt (`#format-03`) | Prompt action placed beside the component or form preview it builds | Copies the feature-specific guide bootstrap |
| Command palette (`#format-04`) | `Cmd/Ctrl + K` opens modal search; `ArrowDown`/`ArrowUp`/`Home`/`End` move focus; `Enter` copies; `Escape` closes; empty query match announces `role="status"` hint | Closes other open dialogs first; copies selected task payload |
| Linked guide (`#format-05`) | Single-sentence copy action paired with a direct link to `/guides/{slug}.md` | Copies bootstrap or opens the readable Markdown guide |
| Open in agent (`#format-06`) | Named launch link (`Open in Cursor`) paired side-by-side with `Copy prompt` | Encodes exact resolved payload into verified draft URL; copy fallback remains available |
| Copy activation | Resets button label first (`resetCopyFeedback` + `data-copy-token`), writes clipboard text, then shows `Copied` for 1.8s and polite toast `Prompt copied.` | Exact plain-text payload written once without losing keyboard focus |
| Clipboard rejected or unavailable | Resets button label without showing `Copied`; opens `#prompt-dialog` in manual mode (`Copy the selected text manually.`), focuses and selects `#prompt-text`, announces `Couldn’t access the clipboard.` | Manual `Cmd/Ctrl + C` copies the exact resolved payload; repeated failures reuse the same dialog |
| Inspect prompt (`.inspect` or `#show-payload`) | Opens `#prompt-dialog`, resets `#dialog-copy` feedback and `#dialog-status`, shows character/word count and guide link | Displays exact payload in a `readonly` textarea |
| Logo treatment switch (`Original`, `Black`, `White` in `#logo-treatments`) | Updates `aria-pressed`, `data-logo-treatment`, `/brands/{id}-${treatment}.svg`, `/brands/plate-{light\|dark}.svg`, and polite `#treatment-status` | Compares artwork only; never alters any copied prompt or launch URL |

## Verification that earns the claims

- **First-screen branding gate:** Inspect the **site being built**, not the reference site alone. At `320 × 667` and `390 × 844` CSS pixels, scroll position zero, record the viewport dimensions, visible supported product logos, visible product names, and bounding box of the first usable copy or launch action. The action and authentic logos must fit in the opening viewport together without scrolling, clipping, or horizontal overflow (`documentElement.scrollWidth <= viewportWidth`). Product-mark strips must wrap cleanly on narrow screens. Check loaded image pixels and natural dimensions, not just DOM tags.
- **Transformed appearance (Dark Reader):** Run Playwright with the real Dark Reader extension (such as Dark Reader 4.9.133) in a persistent Chromium context, verify extension identity and an actual page color transformation, then repeat the first-screen and gallery checks at `320 × 667`, `390 × 844`, and `1440 × 1000`. Verify that monochrome marks on darkened surfaces invert cleanly (`.adaptive-mono` / `-white.svg`) while full-color originals retain their palette and black/white comparison swatches keep their cutouts and contrast. Inspect glyphs for unintended emoji rendering and confirm no heading or number ends with a footnote-style star.
- **Footprint and task-first copy:** Inspect the host page at `320 × 667`, `390 × 844`, `768 × 1024`, and `1440 × 1000` CSS pixels. Headings must name the demonstrated task or control rather than slogans or promotional fragments, and adjacent copy must not repeat the same explanation. Count visible UI copy and pasted payload length separately against the 40-word / 300-character review target.
- **Payload parity and feedback reset:** Copy each task and compare clipboard contents against `#prompt-text` in the inspection dialog and any launch link's decoded query parameter. Switch agent picker options and reopen the inspection/recovery dialog after copying to confirm `resetCopyFeedback` clears stale `Copied` labels and status text.
- **Clipboard denial and share recovery:** Deny or stub `navigator.clipboard.writeText` to throw in a controlled browser test. Confirm no `Copied` label or success toast appears, `#prompt-dialog` opens with `#prompt-text` focused and selected, and repeated copy or share failures reuse a single recovery dialog.
- **Keyboard and dialog accessibility:** Exercise every filter (`All seven`, `Copy`, `Launch`), agent picker button, logo treatment button (`Original`, `Black`, `White`), and dialog (`#prompt-dialog`, `#palette-dialog`, `#share-dialog`) using `Tab`, arrow keys, `Home`, `End`, `Enter`, and `Escape`. Verify focus return, `aria-pressed` states, empty-search `role="status"` announcements, and reduced-motion behavior.
- **Guide retrieval and public-source audit:** Fetch every referenced `/guides/*.md`, `/examples/project-handoff.md`, and `/llms.txt` route and verify HTTP 200 and expected Markdown content. When working in `agent-prompts` or a public handoff repo, run `npm run check` (`prettier --check`, `node scripts/audit-public.mjs`, `tsc --noEmit`, `vite build`) and `git diff --check` with LF line endings to confirm zero personal paths, network IPs, nonpublic skill references, credentials, or broken local links, and that all required license notices (`LICENSE`, `public/LICENSE.txt`, `public/fonts/GEIST-OFL.txt`, `public/brands/LOBE-ICONS-LICENSE.txt`, `public/brands/SIMPLE-ICONS-LICENSE.txt`, `public/brands/credits.txt`, `THIRD_PARTY_NOTICES.md`) are present.

For an embedded feature action, the branding and action must be visible together beside the feature; the opening-page gate applies when the page itself is the handoff. If the host cannot load browser extensions, record Dark Reader coverage as unavailable rather than claiming a pass. Use existing project checks; the named scripts and selectors above describe the reference implementation, not prerequisites for every host.

For a prompt-only request, verify the text and referenced guide and return the prompt. For a UI or site request, build and verify the rendered component against these gates. Scale checks to the requested deliverable while keeping first-screen branding and honest copy behavior non-negotiable.
